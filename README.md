# ایجنت بررسی محصولات ترب

نمونهٔ اولیهٔ محلی برای پیشنهاد تصمیم به کارشناس. Python 3.11+ کافی است.
ورودی یک شیء JSON از ورودی استاندارد است و خروجی شامل `decision` و `reason` است.
خروجی جداسازی فیلد `groups` هم دارد.

```bash
python3 agent.py <<'JSON'
{"kind":"merge","category":"cable","left":{"model":"A10","length":"۱ متر"},"right":{"model":"A10","length":"۲ متر"}}
JSON
python3 -m unittest discover -s tests
```

برای ادغام، `left` و `right` شواهد استخراج‌شده توسط کارشناس هستند.
مقادیر ساختار، وضعیت، تعداد و طول را با قالب یکسان وارد کنید. عنوان خام برای
تشخیص واژه‌های وضعیت استفاده می‌شود. مدل و برند باید هویت تجاری را نشان دهند.
پرچم‌های `images_checked`، `cluster_checked` و `single_model_confirmed`
را فقط پس از بررسی واقعی فعال کنید. در صورت تعارض شواهد
`conflicting_evidence` را فعال کنید.

برای جداسازی، `kind` را `split` بگذارید. پس از بررسی کامل کلاستر،
`cluster_checked` و `verified_split_groups` را بدهید. هر گروه آرایه‌ای
از شناسه‌های اعضایی است که باید با هم یک بیس تشکیل دهند.
درخواست حذف به کارشناس ارجاع می‌شود.

دامنهٔ نسخهٔ فعلی هستهٔ پیشنهاددهی است. اتصال به پنل و افزونهٔ Chrome،
استخراج خودکار شواهد، OCR، صف و ارزیابی با داده‌های واقعی مراحل بعدی‌اند.
قواعد مرجع در [سند قواعد](rules/torob-merge-split-rules.md) آمده‌اند.

## اتصال به پنل ترب در Chrome

۱. مخزن را روی مک دانلود کنید. از پوشهٔ اصلی پروژه در Terminal اجرا کنید:

```bash
python3 local_server.py
```

۲. در Chrome صفحهٔ `chrome://extensions` را باز کنید. **Developer mode** را
روشن کنید و با **Load unpacked** پوشهٔ `chrome-extension` را انتخاب کنید.

۳. در [صفحهٔ بررسی درخواست‌ها](https://panel.torob.com/cs/voting/w)،
در افزونه «خواندن درخواست باز و دریافت پیشنهاد» را بزنید. در صورت تغییر
ساختار پنل، عنوان‌ها را با انتخاب متن یا ورود دستی وارد کنید.

نسخهٔ افزونه عنوان‌های درخواست باز را به سرویس روی همین سیستم ارسال می‌کند.
تصویر، کلاستر و نشست ورود به سرویس ارسال نمی‌شوند.

«بررسی و ثبت یک رأی خودکار» درخواست بازِ قاب گوشی را بررسی می‌کند.
اگر دو مدل آیفون صریحاً متفاوت باشند (مثل iPhone 13 و iPhone 13 Pro Max)،
گزینهٔ «تفاوت در مدل» را می‌زند. اگر یکی از عنوان‌ها دو مدل صریح داشته باشد
(مثل 13/14)، گزینهٔ «عدم ذکر مدل در عنوان» را می‌زند.
نتیجه را با مشاهدهٔ درخواست بعدی گزارش می‌کند. در صورت توقف صفحه روی همان
درخواست، وضعیت را در پنل بررسی کنید. تأیید، حذف، جداسازی و سایر دلیل‌های رد
دستی هستند. افزونه درخواست بعدی را خودکار پردازش نمی‌کند.

## آزمایش OpenAI API روی مک

در [داشبورد OpenAI](https://platform.openai.com/api-keys) یک کلید API بسازید و
اعتبار پرداخت پروژهٔ API را بررسی کنید. در Terminal مک (zsh)، پس از توقف
سرویس قبلی با Control+C اجرا کنید:

```zsh
read -rs 'OPENAI_API_KEY?OpenAI API key: '; echo
OPENAI_API_KEY="$OPENAI_API_KEY" python3 "/Users/$USER/Downloads/torob-merge-agent-main/local_server.py"
unset OPENAI_API_KEY
```

در صورت تفاوت محل دانلود، مسیر فایل را عوض کنید. در افزونه گزینهٔ «ارسال
دو عنوان به OpenAI برای موارد مبهم» را روشن کنید، سپس «خواندن درخواست باز
و دریافت پیشنهاد» را بزنید. هر فراخوانی ممکن است هزینه داشته باشد.
تنها دو عنوان و دستهٔ شناخته‌شده ارسال می‌شوند. پاسخ مدل پیشنهاد است.
ثبت رأی همچنان فقط بر اساس قواعد محلی انجام می‌شود. چون مدل در این نسخه
تصویر و کلاستر را نمی‌بیند، تطابق عنوان به تأیید تبدیل نمی‌شود.
مدل پیش‌فرض `gpt-4.1-mini` است و با `OPENAI_MODEL` قابل تغییر است.
